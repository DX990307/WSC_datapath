> **10-22 深夜更新（用户："既然已经知道问题所在，可以直接把这四点加上跑实验试试"）**：不先单独做差距拆解，直接实现四个补丁并做消融（每次关掉一个 = 差距拆解）。四点：
> ① 热点页早识别、一次性拆成 1 KB 块（集中热点散到环 12，分散热点按哈希交错或不动），同 buffer 未访问页一起改映射；

> ④ 只读热点复制（Q5 设计：只给集中在单个 owner 的热点只读页开副本，写或 kernel 边界作废）——会碰一致性规则，用户已同意试，必须开 -verify 和一致性检查。
> 主会话给的默认选择（用户可推翻）：识别和计数在硬件（owner 端小表 + 翻译端读者计数），决定和搬运由 driver 按批做，规律确认后的预放置不走逐页软件处理；普通共享页（2–K_hot 读者）不动；一组全局参数。

**0. 同步 + 配置确认（⏸ 等用户"确认"）**

**1. 差距拆解（先做，决定后面优化什么）**
在 M3+ 上，相对"在线 c4k-class"逐项去掉一个差距来源，和两遍法 oracle 比：
- (a) 迁得晚：第一个 kernel 开始时按 oracle 表一次性迁移（付迁移代价，但不等计数）；
- (b) 迁移代价：`-pm-ideal`（软件延迟、shootdown 为 0），以及再加"拷贝瞬间完成"的变体；
- (c) 粒度：在线迁移改按 1 KB 块（复用 P20 `-place-table` 的 1 KB 块重映射做成可在线更新的表）；
- (d) 组合：(a)+(b)+(c) 应接近 oracle，否则说明还有没找到的来源。
workload：P20 的 16 个。输出每个来源占"oracle − 在线"差距的比例。

**2. 离线规律性分析（不跑模拟，用 P20 pass-1 统计）**
- 每个 buffer：页（或 1 KB 块）号 → 主要使用者 GPM 能否用简单规律预测：线性切分（i → ⌊i / n⌋）、相邻相同、固定步长轮转；报告规律命中率（按远程访问加权）。
- 能多早学到：按首次访问时间排序，迁移（或观察）前 N 页后规律被确认（连续 m 页命中）时，这个 buffer 还有多少页没被访问过（可零代价预放置的比例）。
- 按类别报告；私有放错 / 流式预期规整，热点和随机共享预期没有规律（照旧收益代价判断或不迁）。
- 通过条件：至少 1/3 的 workload 有 ≥ 50% 的被迁字节能被规律覆盖，否则第 3 步只做收益/代价部分。

**3. 自适应迁移算法（原型）**
- 收益/代价判断取代固定阈值 256：
  - 收益 = 预计剩余远程访问数 × 每次能省的延迟（跳数差 × 每跳延迟 + 排队估计）；预计剩余访问 = 最近窗口速率 × kernel 剩余时间估计（或上一个 kernel 同一块的访问数）。
  - 代价 = 固定开销（软件、shootdown、挂起）+ 字节 × 跳；收益 > 代价 × α 才迁。
- 目标：沿用 `-pm-target class`；粒度：同页各块主读者不同 → 按 1 KB 块，否则整页；集中热点按 P20 规则拆到环 12，分散热点不迁；迁过两次固定。
- 规律学习与预放置（第 2 步通过才做）：
  - 学习：前几页按收益/代价迁，记录"页 → 目标"；
  - 确认：同一 buffer 连续 m 页符合同一规律即置信；
  - 预放置：对该 buffer 尚未被访问的页按规律提前迁（无 TLB 失效、无挂起，成批 DMA，不走逐页软件处理）；新分配的 buffer 直接按规律放置；预测错就回退并降置信。
- 统计：每次迁移付了哪些代价（软件 / shootdown / 挂起 / 拷贝），预放置命中率，回退次数。

**3b. 热点页：早识别、一次性拆页，不走迁移（用户 10-22："当读前几个 cacheline 感觉不对了，直接拆页+迁移"；"预测让下一个需要迁移的 page 迁移"）**
- 依据：P20 在线结果里热点页一迁就亏（tc：argmax 1.74、class 2.05、热点不迁 2.27、M3+ 2.39），而 1 KB 哈希交错 2.70 ≈ oracle 2.73。
- 离线先算（pgcls trace / pass-1）：
  - 早识别信号：(i) owner 端前 N 次 line 读里不同读者数（复用 Q2 的读者位图）；(ii) GMMU/IOMMU 端同一页被多少个不同 GPM 走页表（翻译请求比数据访问更早、几乎免费）。报告：达到"≥ k 个不同读者"时，这页已经发生了多少比例的读、离首次访问多久；误判率（被判热点但其实是私有 / 少量共享的页）。
  - 同 buffer 传播：热点页在 buffer 里是否连续成片（例如 PR 的 rank 向量 32 页全热）。若是，第一页被判热点后整片 buffer 一起拆。
- 动作：判为热点的页（或整片 buffer）一次性拆成 1 KB 块，分散到环 12（集中热点）或按哈希交错；拆完固定不再迁。只对拆的那一页短暂挂起；尚未被访问的同 buffer 页直接改映射，无 TLB 失效、无挂起。
- 对比：热点不迁、1 KB 交错（全局）、oracle 拆分，在 PR、tc、MM、npbcg、atax、sssp、IVF 上。
