\section{Observations}
\label{sec:observations}

We trace the Baseline execution of the same 14 workloads used in our
evaluation. O1 quantifies the full memory path. O2 and O3 examine adjacent
local reads and their HBM mapping. O4 and O5 examine remote-path cost and
requester-side aggregation. O6 examines remote-data reuse and available
capacity in the existing requester-GPM L2.

\noindent\textbf{O1: Cost of a Full Memory Path.}
We measure each component from the arrival of a demand read until the
component forwards the request or response. Communication into L1, L2, and
HBM is charged to the receiving component, while requester RDMA, the wafer
network, and owner RDMA are grouped as Remote Communication. We count only
completed MSHR leaders and exclude MSHR waiting. Figure~\ref{fig:obs-full-path}
shows that HBM and the Local GPM L2 Cache account for 65.8\% and 31.0\% of
the weighted local full-path latency. Remote Communication contributes
70.0\%--98.8\% of each qualifying remote path and 97.0\% when weighted across
those paths. Figure~\ref{fig:obs-l2-miss} further shows that local demand-read
miss rates range from 2.8\% to 100\%, although every miss still pays the full
tag-lookup latency. The opportunity therefore includes both avoiding
known-miss cache work and reducing downstream memory and communication work.

\noindent\textbf{O2: Adjacent Local Read Misses Exhibit Short-Window Correlation.}
Across 13 of 14 workloads, 5.0\%--50.0\% of local L2 read misses have a
preceding read miss for the paired adjacent cacheline within 16~ns (see
Fig.~\ref{fig:obs-adjacent-window}).
We measure the interval between local L2 read misses to the two cachelines in
the same aligned HBM region.
Together with O3, this result shows that short-window adjacency
provides a practical opportunity to exploit HBM row locality through
selective paired reads.

\begin{figure}[!t]
  \centering
  \includegraphics[width=\columnwidth]{../../akkalat/results/2026-07-23-23-41-05-sampled-validation/o2-diagnostic/o2_adjacent_correlation.pdf}
  \caption{Short-window adjacent correlation among local L2 read misses. Each
  bar reports the fraction of selected misses with an earlier miss for the
  paired adjacent cacheline within 16~ns. Selected requests are completed
  MSHR leaders that miss in both L1 and L2 and reach local HBM.}
  \label{fig:obs-adjacent-window}
\end{figure}

\noindent\textbf{O3: Adjacent Reads Preserve HBM Row Locality.}
We map every physical read to its HBM bank, row, and column. Within 16
controller cycles, 29.1\% of reads find an earlier read in the contiguous
two-cacheline region of the same HBM row, while only 6.2\% find an earlier
read at another column of that row, as shown in
Fig.~\ref{fig:obs-dram-locality}. The adjacent relation observed at L2 is
therefore also the strongest relation exposed by the HBM mapping. A paired
read can exploit this locality, provided that cache and in-flight state first
remove an adjacent line that is already available.

\noindent\textbf{O4: Remote Accesses Amplify Work Across the Wafer.}
Remote accesses travel an average of 3.0 to 6.6 mesh hops between requester
and owner GPMs. Including execution at both RDMA endpoints and the return
network path, mean end-to-end remote-access latency ranges from 465 to
7{,}787 cycles across workloads. Figure~\ref{fig:obs-remote-amplification}
reports both measurements. The long path consumes RDMA state and multiple
network links before owner L2 can process the request. Owner-L2 coalescing can
reduce subsequent memory work, but cannot recover endpoint and network
resources already consumed. Requester-GPM RDMA is the first shared component
that observes requests from different L1 caches before network injection.
These results motivate aggregating remote requests at requester-GPM RDMA so
that redundant accesses do not repeat the full wafer traversal.

\noindent\textbf{O5: Remote Requests Can Be Aggregated at Two Granularities.}
Figure~\ref{fig:obs-remote-aggregation} shows two request relations visible at
requester-GPM RDMA. Depending on the workload, 0\%--91.9\% of remote reads
duplicate an in-flight request for the same cacheline. After removing those
duplicates, another 0\%--75.0\% of the original remote-read stream targets a
different cacheline within the same requester GPM, owner GPM, and 4-KB page
during a 16-cycle window. Weighted across all remote reads, the two relations
account for 25.9\% and 23.1\% of the stream. Same-line aggregation avoids a
redundant remote access, while same-page aggregation carries different
cacheline requests in fewer network packets. Processing both relations at
requester-GPM RDMA prevents unnecessary traffic before the requests enter the
wafer network.

\noindent\textbf{O6: L2 Cache Has Spare Capacity for Reused Remote Data.}
Depending on the workload, 0\%--100\% of unique remote cachelines are accessed
more than once, as shown in Fig.~\ref{fig:obs-remote-recurrence}. Weighted
across all remote cachelines, 17.7\% exhibit reuse, and third-or-later accesses
account for 22.0\% of the remote-read stream. Figure~\ref{fig:obs-l2-headroom}
shows that mean free capacity in the existing GPM L2 Cache ranges from 9.8\%
to 94.1\% across workloads and averages 60.1\%. The available L2 Cache
capacity can therefore store remote cachelines that have demonstrated reuse.
After a second access confirms reuse, the returned cacheline can be installed
in the existing L2 Cache, allowing later accesses to complete locally without
another wafer traversal or a new cache level.

Together, the observations identify three concrete decision points. Local L2
can reject known-miss tag work and recognize adjacent demand with favorable
HBM mapping. Requester-GPM RDMA can remove same-line requests and combine
same-page traffic before network injection. Returned remote data can establish
reuse before another wafer traversal occurs. CuPath connects these decisions
with shared membership state while exact cache, MSHR, and RDMA structures
preserve correctness.
