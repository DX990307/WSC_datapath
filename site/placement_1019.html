原因 1：WG 段和页段错开

页：每个 buffer 按页 48 等分，第 i 段放在第 i 个 GPM。WG：每个 CU 分 ⌈N / 总 CU 数⌉ 个，第 i 个 GPM 连续拿 CU 数 × 这个数。两种切法只有在 N 恰好是总 CU 数的整数倍时才对齐。下面按公式画出“每个 GPM 的 WG 读的数据有多少在自己的页上”（假设每个 WG 读等量的连续数据，只用来说明机制）。

原因机制影响到的证据
WG 段和页段错开WG 按 CU 数连续切（每 GPM 28 × ⌈N/1344⌉ 个），页按 48 等分；N 不是 CU 总数的整数倍时，两者逐渐错位kmeans（hpca 0% → mi200 42.9% 远程读，baseline 慢 3.70 倍：4.24 ms → 15.68 ms）10-15 放置统计、短片段 ablation 的 baseline 时间

小 buffer 整个放在 GPM 1buffer 小于 48 页（192 KB）时不切分MM 小输入（64 KB 的 B 矩阵）、R-GAT（tile 0 占 7.1%）T16 热力图、T17 owner 统计
余数页给最后一个 GPM页数不能被 48 整除时，余数全给 GPM 48R-GAT（tile 48 占 16.7%）、matrixtranspose（tile 48、47 是前 2 个 owner）T17 owner 统计、诊断 C
WG 向上取整，后面的 GPM 分得少⌈N/1344⌉ 向上取整，最后一个 GPM 只拿到余数matrixtranspose 小输入最后一个 GPM 65 个 WG（其余 112）；默认输入最后一个 GPM 0 个T16
数据和计算的划分方式不同MoE 的 expert 权重按 buffer 48 等分，expert kernel 的 WG 却只铺到 26–41 个 GPMMoE 远程读 95%T17

候选修正（只给方案，没有实现）

候选做法对 hpca 旧结果对 mi200
P1页段按每个 GPM 的 CU 数占比切，和 WG 段用同一规则hpca 每 GPM 32 CU、本来是等分，预计不变（需要回归确认）影响最大：kmeans 这类错位消失
P2运行时小分配放在发起 kernel 的 GPM，或者复制到每个 GPM改变 hpca 的 0.1–1.8% 远程读，不能逐位复现（加开关，hpca 默认关）去掉 tile 0 的小热点
P3小于 48 页的 buffer 按页交错现有 14 个 workload 没有这种 buffer，不受影响对 T17 和新 workload 有用（R-GAT、MM 小输入）

推荐 P1。用户 10-14 的意见是“保持现状，这也算一个可以优化的点”，所以现在 baseline 没有改；放置是 baseline 的一部分还是作为可优化的点，还需要决定。
