前提：HDPAT 之后是数据访问

HDPAT（HPCA 2026）

中心 IOMMU 的页表遍历是瓶颈 → 把 PTE 缓存在离请求方近的 GPM 上，用 cuckoo filter 快速判断“本地有没有”。解决地址转换。

CuPath（ISCA 2027）

地址转换解决之后，远程数据访问成为瓶颈：端点窗口只放行 64 个请求、排队占远程延迟 80% 以上、owner 端不合并相同 line。

baseline 要体现前提：打开 HDPAT，或用理想地址转换。动机图建议四根柱子：原始 IOMMU → + HDPAT → + CuPath → O1（数据全部本地）。

HDPATCuPath 新机制
对象PTE（基本只读、规模小）数据 line（会写、几百 MB）
做法就近缓存 PTE不缓存、不复制、不迁移，只管请求的流动
cuckoo filter 管的集合“本地缓存了哪些 PTE”（静态）“正在路上的请求”“哪些 GPM 在等同一条 line”（动态，必须能删除）
瓶颈中心页表遍历单元每个 GPM 的端点窗口、owner 端

机制 1（T18）：新 m2，两端合并

新 m2：两端合并（深色框是 cuckoo 表）

部分做法为什么
请求方在途表cuckoo 表，key = 远程 line 地址，项 = 指纹 + 目的 GPM + 等待者指针；命中就挂上去等，响应回来就删除合并重复请求、按索引匹配响应（不用全相联 CAM），可以用小面积撑起上千个在途请求
正确性指纹只做筛选；合并前用完整地址核对（或每项存完整 tag）假阳性如果直接合并，会返回错误数据
按距离分配窗口总上限 W（扫描 64 / 256 / 1024 / 4096），每个目的地的 credit ∝ 往返时间按 Little 定律，6 跳的 owner 要 3.3 倍于 1 跳的名额才能达到同样带宽
owner 端请求者表指纹 + 48 位请求者位图；同一 line 只读一次，沿 XY 树多播incast：k 个 GPM 读同一 owner 时封顶 113 B/周期，相同 line 不合并
和 HPCA 版 m2 的关系保留请求方聚合 / 去重和 typed filter 的面积数据新增 owner 端多播和按距离分配窗口：wafer 特有，回应“机制太通用”

数据支持：远程带宽 = 64 × 64 B ÷ 往返时间（1 跳 26.4、6 跳 8.0 B/周期），链路利用率 < 3%；T17 每个 GPM 有 270–400 个远程读在途，堵在 RDMA 门口；按闭环模型，窗口放大后吞吐最多约 7 倍（待 P12 用 O2b 验证）。

按 T17 trace 估算的完美均衡上限（假设每个 GPM 速度不变、工作可以任意切分）。不均来自数据（序列长度、每个 expert 的 token 数）和静态连续切分，T16 已经排除位置。

部分做法
偷谁每个 GPM 把剩余 WG 数告诉 1–2 跳内的邻居；先跑完的 GPM 从邻居 WG 区间的尾部偷还没开始的 WG。远处的 WG 偷过来要多付 5–10 跳，所以只偷近处
偷哪个（cuckoo filter）同一个 kernel 第一次运行时，用 cuckoo filter 记录每组 WG 读过的页（模式变化时删除）；偷的时候拿候选 WG 组的足迹和自己的在途表、L2 内容比，挑重叠最多的
没有历史时按编号相邻 / 同一组（如 MoE 同一个 expert）挑
和 T18 的关系共用同一张在途表：m2 用它合并请求，WG 窃取用它判断亲和性
workload偷来的 WG 和偷取方的数据重叠亲和性的价值
MoE同一个 expert 的 WG 读同一份权重大
R-GAT相邻目标节点共享邻居特征中
PagedAttention每个 WG 读自己序列的 KV，几乎不共享小（只按距离偷）

风险：要改 driver / dispatcher 的 WG 分配（所有 workload 共用，必须用开关、默认关闭、回归逐位一致）；MCM-GPU 上有分布式 CTA 调度的前人工作。如果测出来亲和性很小，就退回“按距离就近偷”，filter 部分放进讨论。
