## 机制（`isca27/adaptive-pm` @ `f7b83ff`，`-pm-replica-list` + `-page-migration=observe`）
- 列表里的页（原物理页号）在第一次被访问时，零代价在列出的 GPM 上建副本：新帧（每 GPM [6 GB, 8 GB) 区域，从不复用），从主帧功能性拷贝（相当于 host 拷贝时写了多份）。
- 向量访存（L1V 的 AT）读这页时，在 AT 的迁移钩子里把物理地址换成离本 GPM 最近的那份（含 home 本身）；标量 / 取指仍读主帧。
- 任何写：挂起 1 µs（shootdown 延迟）后折回主帧，这页之后不再复制（主帧可能有脏行在 home 的 L2 里）。kernel 边界：主帧内容和副本相同（没有 host 拷贝）就保留副本，否则折回；副本帧在途访问排空后退役。
- 页选择（oracle，`scripts/mkrep.py`，P19 W = 128 baseline 的 pgcls 精确统计）：全程没有任何 GPM 写过、≥ 2 个非 owner 读者、远程读 ≥ 8 的页。k = 4：风车形四象限（各 12 个 GPM tile），每个有读者的象限放 1 份，位置 = 象限内使"该象限读者的读数 × 跳数"最小的 tile（= owner 时不放）；k = 9：3 × 3 区域（x、y ∈ {0,1} {2,3,4} {5,6}）。
- 覆盖（列表页占 baseline 远程读）：PR / IVF / MM / MT 1.00，tc / atax / embbag 0.99，spmv 0.98，bh / sssp / i2c 0.95，MoE 0.38，npbis 0.15，PA 0.04，CFD 0.03，npbcg 0.02，bfs 0.01，MG 0.001；**km、fft2d、fw、gups、lud、ar、shocsort 为 0**（这些页在某个 kernel 被写过；按 kernel 只读需要在线写检测，今晚没做）。这 7 个的复制配置在表里按不复制的同底座计。

## 结论
1. **复制在已有 M3+ 保留之上还有 8–9%**：v4m3+复制4 / v4m3 GMEAN 1.084（25 个；有可复制页的 18 个 1.118），M3++复制4 / M3+ 1.086，first-touch+M3+ 之上 1.091（18 个 1.129）。k = 9 再好一些：M3++复制9 / M3+ 1.108（23 个，MoE、MG 未完）。
2. **收益集中在热点 / 多读者只读数据**（与离线一致：剩余读里 ≥ 4 读者的只读块约 43%）：sssp v4m3 1.51 → 2.60（k = 9 3.56）、IVF 1.22 → 1.77（k = 9 2.03）、MoE 1.11 → 1.48、bh 1.16 → 1.50（k = 9 1.61）、atax 1.55 → 1.77、PR 8.18 → 9.17、tc 2.39 → 2.71、MM 1.69 → 1.79、i2c 1.22 → 1.28、npbis 1.11 → 1.18。热点广播类 GMEAN：v4m3 1.975 → 2.317，M3++复制9 2.458；对两遍法放置 oracle（P-按类+M3+）在热点类上已经 1.10×。
3. **无效**：npbcg、MG、bfs、MT、PA、spmv、embbag、CFD（±2%；可复制的读少，或读者各读不同 line）；私有放错 / 流式要靠放置（first-touch），复制管不了：M3++复制4 / oracle 在私有放错类 0.52、流式 0.68。
4. **和 first-touch 正交、可叠加**：first-touch+M3+ / M3+ 1.226（私有放错 1.61、流式 1.36、混合 1.29、热点 1.10）；first-touch+M3++复制4 相对 baseline **1.900**（25 个），是今晚最好的组合；oracle P-按类+M3+ 2.246（14 个）、全部本地 2.799（14 个）。
5. 复制以后打包 / 合并几乎没作用：v4m3+复制4 / M3++复制4 = 1.001。
6. 需要小心的数字：sssp 的 M3++复制9 = 3.562 超过了"全部本地"2.804（全部本地是 P20 的单次运行、也未必是严格上限；本结果未验证正确性），IVF 的全部本地本身就是无效运行（指令数不符，*）。正式数字要在 -verify 和在线判断版本上重测。
