# P20 结论：放置（两遍法 oracle / 迁移时选目标）+ M3+

Claude Code，2026-10-23。场景见 `README.md`。所有数字是相对 baseline（原版 RDMA，W = 128）的加速比；GMEAN 只算有效运行。P20 按用户决定提前结束，`-pm-target` 只跑完 209 / 352 个运行，下面的在线结论按"同一组 workload"比较。

## 0. 结论

1. **上限很大**：两遍法 oracle（分配时就放好，无迁移开销）P-按类 v2（热点集中时拆到中心环 12 个 tile，其余页 1 KB 子块给主要使用者）+ M3+：**GMEAN 2.25（14 个）**，对 M3+（1.55）**1.45×**，离全部本地（2.86，13 个有效）还差 1.22×。三条"砍掉"门槛都过了：子块 / 整页 1.22（门槛 1.03）、热点拆分 / 整页放中心 1.44（PR、tc、MM，门槛 1.03）、P-按类 + M3+ / M3+ 1.45（门槛 1.05）。
2. **在线（迁移时选目标）拿不到这个上限**：同一组 11 个 workload 上，M3+ 1.62，M3+ c4k（argmax）1.67，M3+ c4k-median 1.69，**M3+ c4k-class 1.70**，M3+ c4k-class-stay 1.72，而 oracle P-按类 + M3+ 2.56、全部本地 3.13。全部有结果的 workload 上：**M3+ c4k-class / M3+ = 1.048（12 个），低于 1.05 的门槛**；c4k-median / c4k（多读者）= 0.975（7 个），**低于 1.03 的门槛**；oracle / 在线 class = 1.51。
3. **目标选择本身只贡献 1–3%**：M3+ class / M3+ argmax 1.018；不叠 M3+ 时 class / argmax 1.036。class 的好处主要是**少迁、少来回**（FW 来回 205 → 3、pin 56 → 3；CFD 来回 125 → 0；tc 来回 86 → 5），而不是迁得更准。median 单独用对热点 workload 有害（PR 1.16 对 argmax 1.55，不叠 M3+）。
4. **在线和 oracle 的差距来自触发晚和粒度**，不是目标：
   - 单 kernel、早期就决定访问模式的 workload（KM、PR、tc、MM）要等某个 GPM 对一页有 256 次远程访问才迁，迁的时候大部分访问已经发生；KM 不叠 M3+ 时所有计数迁移都**变慢**（0.87），oracle P-子块 2.47。
   - 4 KB 页粒度：KM、MoE、CFD、PA 的 oracle 收益主要来自 1 KB 子块（P-子块 / P-整页：KM 2.68、CFD 1.68），4 KB 迁移拿不到；PA oracle 2.13，所有迁移 ≈ 0.99；MT 两者都是 1.00。
   - 热点集中的 PR：oracle 12.9，在线 8.4（≈ M3+ 8.2）；拆到中心环需要一开始就放好。
5. **其他迁移机制**：on-fault 4K（M3+ 上 1.13，GMEAN 低于 M3+）、counter 2M（0.57，全面变差，和 pm 一致）、1 KB 细粒度交错（M3+ 上 1.46，热点 workload 上好：tc 2.70、PR 8.85，私有放错和 sssp 上差：FW 0.90、KM 1.30、sssp 1.10）、只迁私有放错页（Q6，M3+ 上 1.81（10 个），和 class 持平：class / Q6 = 0.99）。**打包 + 合并（v4m3）在 W = 128 下对放置没有额外收益**（oracle：P-按类 + v4m3 2.240 对 + M3+ 2.246）。
6. **med（访问者加权中位）对主要使用者**：离线读×跳略低、远程读略多、最忙链路更集中；时序上没有差别（oracle P-med / P-按类 0.996，+ M3+ 1.003，7 个）。
7. 对 P21 的启示：值得做的是"早放对"（分配时 / 首次触碰 / 编译器提示）+ 子块粒度 + 热点集中时拆分，而不是改迁移目标；迁移目标用 class 规则主要价值是抑制来回迁。
