## 0. 结论

1. **A1 本身（只保留只读副本）收益很小**：GMEAN 对 v4 **+0.5%**（bfs +6.0%、CFD +4.5%、ar +1.7%、FW +1.3%，其余在 ±0.7% 内）。两个原因：
   - 9 个 workload 在模拟窗口里**只有 1 个 kernel**（PR、MM、TC、I2C、gups、MT、SpMV、embbag、sssp；A1 纪元数 = 1），根本没有边界；
   - 有边界、而且 A1 确实省下网络 line 的地方，**W = 256 时网络 line 少了也不一定变快**：npbcg 网络 line −74%（T18 窗口满的时间比例 41% → 2%），时间 −0.7%；MG −8%，±0。W = 256 下这两个 workload 已经不受远程窗口限制（W = 64 应该不同，这次没跑）。
2. **dm 分析里的 "A1 余量" 大部分不是跨 kernel 的重复取**（第 2 节）。新基线 v4 的计数表明：
   - 单 kernel workload 的"同 GPM 重复取"**几乎全是 M3 的两次触碰准入**：一条 line 第一次只有一个请求者时只记 SEEN、不填 L2，第二次触碰还要再走一次网络才填（PR 33%、MM 27%、I2C 36%、TC 32%、sssp 39%、bh 36%、npbis 48% 的网络 line 是这类"第二次取"）；**没有容量驱逐**（PR / MM / I2C 的副本驱逐数为 0，L2 远没满），**也没有在途重复**（在途合并由 M1 处理，第三次触碰都命中 L2）。
   - KM、fft2d、FW、MG、CFD、gups、LUD 的重复取主要来自**"本 GPM 写过的远程 line 永久不可缓存"**（`remoteUncacheable`，写时设置、从来不清，跨 kernel 也不清）：KM 100%、fft2d 79%、FW 64%、MG 53%、CFD 49%、gups 40%、LUD 33% 的网络 line 落在这类 line 上。A1 管不到它们。
3. **把这两处放开才有收益**：
   - 首次触碰准入（v4+ft2，不开 A1）：GMEAN +1.7%；PR 网络 line −33%、+4.8%；TC −25%、+8.6%；bfs −14%、+10.8%；FW +5.7%；npbis +3.5%；MM −27% 但时间不变；**sssp −2.4%、fft2d −3.0%**（变慢）。ft1（只填空闲 way）和 ft2 在跑过的 7 个上差别很小（FW、KM、npbcg 完全一样；bfs、sssp ft1 更好：sssp ft1 +0.5% 对 ft2 −2.4%）。
   - 边界清除不可缓存标记（v4+A1+reset）：KM **1.39×**（网络 line −70%）、FW 1.12×、CFD 1.07×、MG +2.4%；GMEAN +2.1%。
   - 全部合用（v4+A1+reset+ft2）：GMEAN 对 v4 **+4.9%**，对 baseline 从 1.315× 到 **1.379×**；KM 1.65×、FW 1.27×、CFD 1.10×、TC 1.09×、bfs 1.07×、PR 1.05×；变慢的只有 sssp（−2.4%）和 fft2d（−1.3%）。
4. **正确性**：A1 关闭时与基线逐位一致；所有 `-verify` 都通过，包括 256 个 kernel 的完整 Floyd-Warshall（每个 kernel 读前面 kernel 写的行 / 列；A1+reset 下 19.9 万行在边界失效、保留后 102 万次跨 kernel 命中）。KM 的 `-verify` 在所有配置（包括 baseline mi200）下给出**同样的**错误值，FW-p12small（截断到 4 遍）在所有配置下都不可能通过，这两个是 benchmark 本身的问题（第 4 节）。
5. **硬件代价**（精确写集合，主实验用的）：每个 home 每个纪元最多写 1364 个 4 KiB 页（PA），moe 有一个纪元全 wafer 写了 13.5 万页。精确列表广播不现实，需要 Bloom 签名（已实现 `-a1-signature-bits`，假阳性只会多失效），但**主实验没有评估签名**，只在小输入验证里跑过 1 Kbit。

## 2. 单 kernel workload 为什么 Complete 之后还有大量同 GPM 重复取

用户 10-22 的问题。数据：新基线 v4（pgcls 的 v4_complete 运行）的计数，按 GPM 求和后除以网络 line（`remote_wire_lines`）：

- 首次取（未准入）= `remote_first_touch_lines`：取回后没填 L2 的 line（第一次触碰、只有一个请求者），之后只在 SEEN 过滤器里留记录；
- 第二次取 = `remote_second_touch_admissions`（SEEN 命中 → 探测本地 L2 落空 → 再取一次并填 L2；与 `remote_l2_probe_misses` 是同一批事件）；
- 自己写过 = `remote_reuse_write_uncacheable_skips`：本 GPM 写过、被永久标成不可缓存的 line 上的读，一律走网络；
- 另外，第一次取时如果有多个请求者合并（`multipleDemandAdmission`），第一次就会填 L2，所以 PR 的填入数（9.76 万）≈ 第二次取（4.87 万）+ 第一次就准入的（约 4.9 万）。

解读：

- **PR、MM、I2C、TC、sssp、bh、npbis、embbag**：第二次取占网络 line 的 13–48%，没有容量驱逐（PR、MM、I2C、bh 为 0），也没有自己写过的 line——"重复取"就是两次触碰准入多出来的那一次。ft2 让它们的网络 line 恰好减少这一部分（PR −33%、MM −27%、I2C −36%、TC −25%、bh −37%）。省下的这一次是否变成时间，取决于 W = 256 下远程读是否在关键路径上：PR +4.8%、TC +8.6%、bfs +10.8%，MM、I2C、bh ≈ 0。
- **KM**：几乎 100% 的远程读落在本 GPM 写过的 line 上。kmeans-t16small 先由各 GPM 用 transpose kernel 把特征转置写到 `dFeaturesSwap`（多数是远程写），之后的 compute kernel 反复读这些 line——但写者已把它们永久标成不可缓存。准入放宽对它完全没用（ft2 = 1.000），A1 也没用；边界清除标记后网络 line −70%、1.39×，再加 ft2 1.65×。
- **fft2d、FW、MG、CFD、gups、LUD**：同上，自己写过的占 33–79%；reset 对 FW（1.12×）、CFD（1.07×）、MG（+2.4%）有效；fft2d、LUD 没有收益（fft2d 每个 kernel 都重写数据，跨 kernel 没有只读重用）。
- **ar、MT、pa、ivf**：有容量驱逐（ar 17.4 万、MT 17.3 万、pa 28.5 万次副本被替换），首次取占 58–82%，属于流式 / 一次性访问，三种机制都没用。
- **npbcg、MG、CFD**：边界失效是主因（npbcg 136 万、MG 112 万、CFD 50 万），A1 正是针对它的，网络 line 分别 −74%、−8%、−15%。

## 5. 建议

1. 论文里 A1 不宜单独作为机制：单独只有 +0.5%。值得保留的是三件事合在一起的"M3 的保留策略"：跨 kernel 保留（A1）+ 边界解除写者的不可缓存标记（reset）+ 首次触碰准入（ft，按 workload 有正有负，sssp、fft2d 变慢；ft1 在 sssp 上不变慢，值得在 25 个 workload 上补跑 v4+A1+reset+ft1）。
2. dm 的 "A1 余量" 指标应拆成：两次触碰准入、自己写过不可缓存、边界失效、容量驱逐四类（本目录 `m3_wire_breakdown.csv`），否则会误导。
3. npbcg / MG 网络 line 大降但时间不变，说明 W = 256、384 GB/s 下它们不再受远程窗口限制；如果要展示 A1 的价值，需要 W = 64 或更大的 wafer 的结果（没跑）。
4. 写集合广播的代价需要评估签名模式（`-a1-signature-bits` 4–16 Kbit）对 moe、pa、mt 这类大写集合 workload 的假阳性。
