# 按访问模式给 25 个 workload 分类，并对照各部件的效果（10-21）

> 数据：主配置 384 GB/s、W = 64（目前所有部件都有结果的场景）。特征来自 baseline 的统计（`dm/raw/`）；部件效果来自 `abl3c384/README.md` T3/T4、`pm/pm.csv`、`geo/`。
> 主配置已改为 W = 256（10-21），打包在 W = 256 下价值会下降，组合后要在 W = 256 下重新验证。

## 1. 特征的定义

| 特征 | 定义 |
|---|---|
| 热点份额 | 发往最大 owner 的远程读占比（在途采样估计，偏向慢的 owner） |
| 共享比例（10 µs） | 落在"同一 10 µs 窗口内被 ≥2 个 GPM 读"的 line 上的远程读占比 |
| 平均共享者 | 被共享的（窗口，line）平均有几个不同 GPM 读 |
| ≥16 读者 | 落在被 ≥16 个 GPM 读的 line 上的远程读占比 |
| 共享者相距 | 同一 line 的共享者两两的平均曼哈顿跳数（随机两个 GPM 是 4.72） |
| 同 GPM 重复读 | 同一（GPM，line，写纪元）第 2 次及以后的远程读占比（整个运行） |
| A1 余量 | Complete 之后，仍走网络的 line 里属于"同 GPM 重复取"的比例（`dup_same_gpm.csv` 的 repeat_net_fetch_frac_of_net） |

## 2. 分类规则

1. 热点份额 ≥ 0.5 且共享比例 ≥ 0.3 → **热点广播**
2. 平均共享者 ≥ 10 或 ≥16 读者 ≥ 0.2（热点份额 < 0.5）→ **轮转广播**
3. 共享者相距 ≤ 3 跳 → **亲和 / 区域**
4. 共享比例 ≥ 0.3 且共享者相距 ≥ 3.5 跳 → **随机共享**
5. 共享比例 < 0.1 → **私有**（再按同 GPM 重复读分：≥ 0.5 自己反复读；否则私有放错或流式）

## 4. 每类的现状和缺口

| 类型 | 现在起作用的 | 有害的 | 缺口 → 要针对的部件 |
|---|---|---|---|
| 热点广播 | M3（最大）、合并、geo-push | 页迁移（PR −24%、graphtc −17%） | A1（npbcg 0.82、PR/graphtc 0.39）；对这类页**禁止迁移**；geo-push 只对这类开 |
| 轮转广播 | 合并、打包 | — | **生产者推送**（未测）；A1（FW、npbis 0.55）；FW 上迁移 +64% 说明还有放错的部分 |
| 亲和 / 区域 | 打包（主要）、迁移（CFD、MG） | geo-push 推几何邻居无效（CFD） | **亲和推送**（在测）；A1（MG、CFD、shocsort 0.5–0.6）；迁移只对这类和私有类开 |
| 随机共享 | 打包、M3（sssp、BH） | 推送（48 GB/s 下变慢）、迁移（BH −9%） | 基本只有 A1（sssp 0.43、BH 0.37）；**不推送、不迁移** |
| 私有 | 迁移（fft2d、I2C、KM）、打包 | — | 迁移（I2C 用缺页即迁更好）；A1（KM 0.93） |

## 5. 结论：针对性的组合

1. **A1（跨 kernel 保留只读）覆盖面最广**：五类里有四类都有 0.4–0.9 的余量，应该最先做。
2. **迁移必须按类型开关**：对私有、亲和、轮转广播有益（+12% 到 +64%），对热点广播有害（−6% 到 −24%）。所以分类器的第一个作用是"哪些页不迁"。
3. **推送按类型选目标**：热点广播 → 推给邻居或区域（geo-push）；亲和 → 推给伙伴（亲和推送）；轮转广播 → 推给所有人（生产者推送，要做）；随机共享 → 不推。
4. **M1（打包 + 合并）对所有类都保留**，是随机共享类唯一有效的部件。
5. 有些 workload 是混合的（例如 npbcg 既有热点广播的 x 向量，也有可迁移的私有部分：迁移叠加 +14%），所以分类最好按页而不是按 workload。按页的分类需要页共享 trace（`-page-sharing-trace`），见下一步。
