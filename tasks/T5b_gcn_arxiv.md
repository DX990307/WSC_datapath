## 为什么选它

- 图学习是 2020 年以后的主流负载，OGB 是公认的标准数据集。
- 在幂律度分布下，热点顶点的特征会被分布在很多 GPM 上的 WG 读取，正好对应机制 1。
- 图结构（CSR）在两层之间只读，可以验证机制 2 的跨 kernel 保留。
- 规模合适：特征矩阵约 87 MB，比单个 GPM 的 L2 大得多，又不超过全 wafer 的 L2 总量（`cu32` 下为 192 MB）。在 `cu8` 下（48 MB），它比 L2 总量还大。

## 规格

- **数据集**：ogbn-arxiv，169,343 个点、1,166,243 条边、128 维特征。做对称化，加自环，用 GCN 的对称归一化。
- **模型**：2 层 GCN，隐层 128，输出 40 类，只做推理（前向）。
- **每层的 kernel**：
  1. **SpMM 聚合**：用 CSR 按行处理，每行 gather 邻居的特征并加权求和。一行对应一个 wavefront 或一个 WG。
  2. **GEMM**：特征 × W（128×128，第二层为 128×40）
  3. **ReLU**（只在第一层）
- **估计 footprint**：特征约 87 MB；CSR 中 col_idx 约 9.3 MB（对称化后约 230 万条边），row_ptr 约 0.7 MB。

## 要做什么

1. 写一个 Python 脚本：用 `ogb` 包下载数据集 → 对称化、加自环、算归一化系数 → 输出二进制的 CSR（row_ptr、col_idx、val）和特征文件（float32）。**脚本和它的输出路径都写进 meta。**
2. 写 kernel，在 MGPUSim 的 benchmarks 下新建 benchmark，Go host 代码负责读取二进制文件。
3. 用模拟统计做合理性检查，**不单独跑 verify**（用户 10-12 的决定）：①`kernels_completed` 等于预期的 kernel 数；②实际访问的 footprint（T2 的 F）和按数据结构大小估算的值相差不超过 20%；③日志里没有越界地址或 page fault 警告。kernel 参数没对齐时，通常会出现 footprint 异常小或者地址越界，这三项能把它查出来。
4. 在 `cu8` 下跑 baseline，确认能跑完两层。

## 调研补充（10-12，Cowork 侧）

- OGB 提供不依赖深度学习框架的加载器：`from ogb.nodeproppred import NodePropPredDataset`，返回的是 numpy 数组，不需要安装 PyTorch。
- ogbn-arxiv 是**有向图**（引用网络），要自己做对称化。ogbn-products 是无向图，加载时边会自动翻倍。
- 统计：arxiv 有 169,343 个点、1,166,243 条边、128 维特征、40 类；products 有 2,449,029 个点、61,859,140 条边、100 维特征、47 类。products 在 T9 中可以作为扩展规模的选项。
